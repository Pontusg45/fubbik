# Vector Embeddings

Each chunk gets a 768-dimensional vector embedding generated by Ollama's `nomic-embed-text` model. These vectors enable semantic search — finding chunks by meaning rather than exact keyword match.

## How Embeddings Work

1. The chunk's title and content are concatenated
2. The text is sent to `nomic-embed-text` for encoding
3. A 768-dimensional float vector is returned
4. The vector is stored in the `embedding` column (pgvector)
5. Cosine similarity queries use the `<=>` operator

## Refresh Behavior

- Embeddings auto-refresh on title or content edit (fire-and-forget, logged on failure)
- The `embeddingUpdatedAt` timestamp tracks when the embedding was last generated
- The knowledge health dashboard flags chunks with stale embeddings (content changed after embedding)

## Powered By

- **Model**: `nomic-embed-text` via Ollama
- **Dimensions**: 768
- **Index**: HNSW (Hierarchical Navigable Small World) for approximate nearest neighbor
- **Database**: pgvector extension in PostgreSQL
